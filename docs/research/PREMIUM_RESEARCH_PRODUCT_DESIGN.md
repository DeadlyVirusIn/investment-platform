# Premium Research Product — UX & Product Design (DESIGN ONLY)

**Status:** design only. **Do NOT implement** premium monetization
code without separate explicit approval. **No** billing, subscription
checks, or run buttons added by this document.

---

## 1. Product positioning

This is **not** an AI trading signal product.

This is a **premium research intelligence and auditability product**.

### What we sell
- Clarity of the research artifact
- Provenance: provider, model, prompt hash, generated time
- Evidence-backed research summaries
- Historical research context
- Audit trail (who/when/why a note exists)
- Freshness signaling
- Transparency into model + cost behavior

### What we explicitly do NOT sell
- Predictions
- Buy / sell / hold signals
- "Best trades" or "high-conviction picks"
- Confidence scores presented as advice
- Price targets / stop-loss / take-profit
- Portfolio allocation guidance

Free-tier variant: every section after the banner+byline is a
locked card with copy:
> "Upgrade to view the full research note and supporting evidence."

### 3.B. Research Timeline

Chronological list of research notes for one asset.

- Filter: provider, model, date range, status
- Each row: byline + freshness badge + status chip
- Click expands the row in-place (or opens panel 3.A)
- Unsafe rows render the safety-failure card; body never displayed

### 3.C. Research Pulse (Dashboard widget)

- Latest 5 generated notes across the watched universe
- Per row: ticker, freshness badge, byline (provider only at Free)
- Empty state: "No research notes recorded recently."
- **No directional color semantics.** Yellow/grey only.

### 3.D. Enterprise Audit View (internal-only / Enterprise tier)

Tabs:
- **Operators:** state, cooldown, last alert, history (read-only)
- **Alerts:** severity, type, status, message, age, dedup info
- **Audit:** manual_run audit rows; metadata-only (no body)
- **Usage:** cost today, runs today, accept/reject/error counts
- **Compliance export:** bundle (markdown + JSON) signed by server;
  always includes the safety banner

No action buttons except "acknowledge alert" (CLI-only path
recommended; UI button optional and gated by separate phase).

## 6. API needs (GET-only; reuse existing endpoints)

| Tier | Endpoints used |
|---|---|
| Free | `GET /api/research/ticker/{symbol}/latest` (returns provenance only when tier=free) |
| Pro | `GET /api/research/ticker/{symbol}/latest`, `GET /api/research/runs?symbol=X`, `GET /api/research/runs/{run_id}` |
| Enterprise | All of the above + `GET /api/research/usage/summary`, `GET /api/research/alerts`, `GET /api/research/operators`, `GET /api/research/operators/{id}`, `GET /api/research/audit` |

**No POST from any premium UI.** The Phase E + E.1 + E.2 + E.3
write paths remain admin-token / CLI-only.

### Server-side tier policy (design — do NOT implement now)
- A small middleware computes the caller's tier from existing
  entitlement system (when one is approved).
- For Free callers: response payloads strip `body`, `outputs`,
  `evidence_refs`, and prompt_hash.
- For Pro callers: cost fields stripped; everything else returned.
- For Enterprise callers: full payload + audit + usage + operators.
- All tiers always receive the safety banner string and the
  fail-closed sanitized payloads (`safety_status='unsafe'` → body
  null) — that contract is already enforced by `_safe_body_or_blank`.

## 8. Rollout plan

1. **Internal-only beta.** Enable Enterprise view for `internal`
   operator group. Watch for: alerts/min, rejected-note ratio,
   cost-per-day per operator, operator-state distribution.
2. **Pro tier behind feature flag.** Read-only research panels
   only. No export. Monitor: locked-vs-unlocked impressions,
   safety_status distribution, body-render error rate.
3. **Add export.** Enforce safety banner on every export artifact.
   Test the markdown bundle through a token scanner CI step.
4. **Pro read-only timeline.** Per-asset chronological feed.
5. **Pro source-reference rendering.** Only when evidence_refs
   structurally validated and pass token scan.
6. **No manual-run UI.** Manual research runs stay CLI/admin-only
   until a separate, explicitly approved phase introduces a
   gated UI trigger (which would be a PRODUCT decision, not a
   research-layer decision).

### Rollback
- Tier feature flag → off → premium UI components unmount
- `RESEARCH_RO_ENABLED=false` → all `/api/research/*` 404
- No DB rollback required for premium UX layer (no schema change)

## 9. Why premium is safe to sell here

The research layer's safety contract is **multi-layer**:

1. DB CHECK on `body` / `bullish_summary` / `bearish_summary` /
   `tension_note` / `reflection.body` rejects every forbidden token
   at INSERT time.
2. Server `assert_no_action_language()` mirrors the regex, runs
   before INSERT and before API response shaping.
3. `_safe_body_or_blank()` strips body to `null` and sets
   `safety_status='unsafe'` when filter trips.
4. Client `scanForbiddenTokens()` re-scans every body the API
   returned and renders `ResearchSafetyFailure` instead.
5. `ResearchBanner` mandatory on every research-aware component;
   render-time throws if banner context prop missing.
6. Premium UX layer adds NO write paths — only consumes existing
   GET endpoints.
7. Premium tier policy strips additional fields per tier; never
   re-enables anything stripped earlier.
8. Locked-state copy is enforced by token-scan CI test
   `test_locked_copy_has_no_signal_language`.

Therefore the worst legitimate failure mode of a premium
deployment is "user sees an empty panel". The system cannot leak
recommendation language, action wording, or provider raw output
without breaking at least three independent safety layers
simultaneously.
