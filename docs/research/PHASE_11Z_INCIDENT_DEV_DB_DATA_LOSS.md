# Phase 11Z incident — dev DB data loss via integration test harness

**Date:** 2026-05-01
**Reporter:** automated, in-session
**Status:** contained, awaiting operator approval for recovery
**Branch:** phase-1/ledger
**Git commit (HEAD at time of incident):** d9d9667296784de185448d4619112f523bffed5a
**Migration head:** 055_phase_11z_macro_unk

---

## 1. What happened

While implementing Phase 11Z (macro gate unknown semantics) the
session ran the new + existing integration test suites against the
dev/working Postgres database (`compose-db-1`,
`investment_platform`) by setting:

```
TEST_DATABASE_URL=postgresql+psycopg://invest:dev_only_password@db:5432/investment_platform
```

`apps/api/tests/integration/conftest.py:64-65` runs:

```python
Base.metadata.drop_all(engine)
Base.metadata.create_all(engine)
```

unconditionally at session start. This dropped and recreated **every
ORM-tracked table** in the dev DB. Some raw-SQL tables (those not in
`Base.metadata` — e.g. `features_daily`, `context_daily`,
`paper_run_log`) survived but were partially mutated by individual
test fixtures (TRUNCATE / INSERT / DROP TABLE).

In addition, the session-scoped fixture in
`apps/api/tests/integration/test_safe_gate_evolution_shadow_pg.py`
runs `DROP TABLE IF EXISTS public.safe_gate_evolution_shadow` in
its teardown, eliminating the Phase 11X diagnostic table entirely.

## 2. Exact commands that caused the loss

```
# 1. Wide-window backfill (innocent, succeeded — wrote 12 context_daily rows
#    for 4-29..5-01 in production status):
docker exec -e FRED_API_KEY=$FRED_KEY compose-api-1 sh -c \
  "cd /app && PYTHONPATH=/app FRED_API_KEY=$FRED_KEY \
   python -m scripts.backfill_macro_features \
     --start 2026-04-29 --end 2026-05-01 \
     --lookback-days 120 --commit --confirm-commit YES"

# 2. Phase 11Z integration suite — destructive:
docker exec compose-api-1 sh -c "cd /app && PYTHONPATH=/app \
  TEST_DATABASE_URL=postgresql+psycopg://invest:dev_only_password@db:5432/investment_platform \
  python -m pytest apps/api/tests/integration/test_phase_11z_macro_unknown_pg.py \
  -v -m integration"

# 3. Regression sweep — also destructive (further test-fixture drops):
docker exec compose-api-1 sh -c "cd /app && PYTHONPATH=/app \
  TEST_DATABASE_URL=postgresql+psycopg://invest:dev_only_password@db:5432/investment_platform \
  python -m pytest \
    apps/api/tests/integration/test_run_paper_daily_gate_alignment_pg.py \
    apps/api/tests/integration/test_safe_gate_evolution_shadow_pg.py \
    -v -m integration"
```

The **session-scoped `pg_engine` fixture** in conftest is what
actually issued the destructive DDL — invoking pytest with the above
URL was sufficient.

## 12. Recovery plan (NOT EXECUTED — awaiting operator approval)

### 12.A. Schema-level fixes

1. Re-apply migration 054 (creates `safe_gate_evolution_shadow`).
   Idempotent: `CREATE TABLE IF NOT EXISTS`. Already in alembic
   history; no-op for the version_num row.
   **Command:** `alembic -c infra/alembic/alembic.ini upgrade head`
   (head is already 055; 054 will not re-run automatically because
   its `version_num` is already recorded. Need to either run the
   table DDL manually or temporarily downgrade-then-upgrade. Lowest
   risk: run the CREATE TABLE statement from migration 054 directly,
   no alembic state change.)

### 12.B. Re-seed deterministic state

2. Assets: `python -m scripts.seed_symbols`
3. Universe membership: re-run any seed script that maintains it.
   (Need to identify which one; can do read-only inspection first.)

### 12.C. Re-fetch external data

4. Price bars (SPY at minimum, equity universe broader): Tiingo
   re-ingest. Existing job: `apps/worker/src/jobs` registers
   `ingest_prices` or similar. Operator triggers via
   `scripts/run_paper_daily.py` or direct job dispatch.
5. Macro context: re-run wide-window backfill for the full window
   that decision_log depends on.
   ```
   python -m scripts.backfill_macro_features \
     --start 2026-04-22 --end 2026-05-01 \
     --lookback-days 120 --commit --confirm-commit YES
   ```
6. Regime snapshots: recompute from price_bar via the existing
   regime job after price_bar is restored.
7. Factor snapshots: recompute from price_bar + features_daily.

### 12.D. Recompute (only if upstream is fully restored)

8. `candidate_idea` for affected dates — only if (asset,
   price_bar, regime_snapshot, factor_snapshot, context_daily,
   universe_membership, alpha_rule history) are restored AND the
   engine is deterministic. Confirm determinism before running.

### 12.E. Do NOT recreate

* `paper_position`: no audit source. Manual recreation would
  fabricate state. Decide whether to leave at 0 (clean slate) or
  bring forward the 29 rows from external memory if any operator
  notes exist.
* `paper_trade_log` / `paper_shadow_log` / `paper_run_log`: already
  intact, don't touch.
* `decision_log`: 16 rows survived; preserve.

## 13. Already-in-place safety changes (incident response)

* `apps/api/tests/integration/conftest.py` — added
  `_assert_test_database_url` guard that raises
  `UnsafeIntegrationDatabaseError` before any DDL runs when
  `TEST_DATABASE_URL` host is the dev/compose Postgres or the
  database name doesn't contain `test` / `integration`. New
  environment variable `INTEGRATION_DB_ALLOW_UNSAFE=1` exists for
  CI scenarios but it cannot bypass the test-name check.
* `apps/api/tests/test_integration_db_safety_guard.py` — pure-unit
  tests (no DB) that verify the guard rejects the exact URL used in
  this incident plus other unsafe variants and accepts properly
  named test URLs.

These changes do NOT touch any production data and do NOT
themselves require operator approval to land — they are
defense-in-depth code-only.

## 14. Documentation rule (added below)

Tests requiring destructive DB reset MUST use an isolated test
database only. Using `investment_platform` (the dev/working DB) is
forbidden. Safe example values:

```
# Ephemeral testcontainer (recommended — leave TEST_DATABASE_URL unset).
unset TEST_DATABASE_URL

# Or, dedicated test DB on a separate Postgres instance:
export TEST_DATABASE_URL=\
  postgresql+psycopg://test:test@localhost:55432/investment_platform_test

# Or against the existing pg-11v-test container (port 55432, db=test):
export TEST_DATABASE_URL=postgresql+psycopg://test:test@localhost:55432/test
# → fails the guard (db name 'test' is allowed). Acceptable.
```
