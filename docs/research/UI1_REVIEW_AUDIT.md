# Phase UI-1 Review — freeform-prose audit

**Status**: Audit report. Findings documented. No code touched.
**Date**: Phase UI-1 review window
**Scope**: Verify no hidden freeform AI rationale remains in the stock-equity WebUI outside the two surfaces Phase UI-1 fixed.

## Method

Grep across `apps/web/src` for prose-generation patterns:
- `plainWhat*`, `humanReasoning`, `build*Thesis`, `build*Reason`, `aiNarration`
- Engine-supplied prose fields: `rationale`, `narrative`, `reasoning`, `why_*`
- Rendering surfaces that render those fields directly to user-visible text

Then categorize each hit as: (a) live rendering, (b) doc/comment only, (c) options scope (out of stock UI-1), (d) already fixed.

### REMAINING freeform-prose surfaces in stock UI

Three sites render engine-generated explanatory prose directly to users. None are inside Column 2 of Decisions or PickModal (the two surfaces UI-1 scoped). All are real constitutional risks if the goal is "no hidden freeform rationale anywhere."

#### 1. `Briefing.tsx:62`

```tsx
{narrativeQ.data && (
  ...
  {narrativeQ.data.narrative}
```

- **Source**: `useBriefingNarrative()` hook → backend `briefing_narrative` router
- **What it is**: Daily portfolio briefing prose generated by a separate engine path. Likely freeform text describing the day's portfolio activity, regime, etc.
- **Severity**: HIGH — fully visible to novice users on the Briefing page
- **Disposition**: Phase UI-2 should either (a) audit `briefing_narrative` to confirm it's structured-template not freeform; (b) replace with deterministic-renderer output; or (c) explicitly document that briefing is a separate truth domain and the Phase L deterministic-renderer guarantee does NOT extend to briefing surfaces

#### 2. `Decisions.tsx:1069`

```tsx
<div className="u-label mb-2">Reasoning</div>
<pre ...>
  {state?.reason ?? "(no reason recorded)"}
</pre>
```

- **Source**: `useCurrentState()` hook → operator state endpoint
- **What it is**: System-level "Reasoning" field from CurrentState — different from per-decision `trade.reason` we already removed. Renders raw engine-generated text as a `<pre>` block.
- **Location**: NOT inside Column 2 — sits in a separate Decisions-page operator panel (regime/gates/version inspection)
- **Severity**: MEDIUM — operator-only surface; novice users do not reach it. Still violates "no hidden freeform rationale anywhere."
- **Disposition**: Phase UI-2 candidate. Either remove or wrap with explicit "operator-state diagnostics" caveat banner

#### 3. `ActionCard.tsx:105`

```tsx
<span className="text-text-secondary text-xs truncate flex-1" title={a.rationale_short}>
  — {a.rationale_short}
</span>
```

- **Source**: `ActionItem.rationale_short: string` field from the actions API
- **What it is**: Truncated engine-generated rationale rendered as inline subtitle on action queue rows. Also surfaces as a tooltip on hover.
- **Severity**: MEDIUM — visible in action queue and likely in dashboard previews. Truncated, but still freeform engine prose.
- **Disposition**: Phase UI-2 candidate. Two paths:
  - (a) Replace with a 1-line summary derived from the row's envelope (need backend support — list-of-actions endpoint returning envelope hash per row)
  - (b) Replace with a short structured tag like the skeleton_id display label (e.g. "Momentum breakout · Live") if the row has an envelope; honest-absence text otherwise

## Recommended Phase UI-2 follow-up scope

If the goal is to eliminate ALL hidden freeform rationale in the stock UI, Phase UI-2 must include:

1. **Briefing.tsx** — most user-visible remaining surface
2. **Decisions.tsx state-panel `state?.reason`** — operator surface but constitutional risk
3. **ActionCard.tsx `rationale_short`** — short prose passthrough; needs backend cooperation

The 3 surfaces above are NOT urgent if Phase UI-2 prioritizes truth banners + state chips first. They become urgent ONLY if an operator/novice review surfaces confusion attributable to mixed prose styles.

## Constitutional posture

Phase UI-1 successfully cleaned the two most important surfaces (the primary novice + primary operator reasoning views). The remaining 3 are smaller leaks. The honest position is:

- "Phase UI-1 eliminated the primary freeform-AI-prose surfaces."
- "Three secondary surfaces still passthrough engine-generated explanatory text. They are documented and triaged. They are not constitutional emergencies but they should be addressed before claiming the UI is fully truth-aligned."

This memo IS the verification of "no hidden freeform rationale remains anywhere" — the answer is "mostly true, three secondary surfaces still leak, locations documented, no urgent fix needed."
