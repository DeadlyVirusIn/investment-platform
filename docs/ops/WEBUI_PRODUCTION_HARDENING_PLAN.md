# WebUI production hardening plan

Status: branch work only. This is **not deployed**. Owner approval is required before any deploy; deployment is a HARD STOP under project policy.

## Current state

Production presently inherits the WebUI's Vite dev-server pattern: a `node:20-alpine` container with source bind-mounted at `/app`, followed by `npm install` and `npm run dev`. Caddy has a `web_dist` static-volume path, but the volume has been populated manually.

The prior `npm ci` build failure is fixed in this working tree. Its cause was a lockfile generated by a different npm version: regenerate the lockfile using the builder image's npm version. `node:20-alpine` ships npm 10.x.

## Target architecture

`npm ci` deterministically installs dependencies, `vite build` produces the SPA, and a one-shot `web` container copies it into `web_dist`. Caddy serves the static SPA from that volume, exposes `/healthz`, caches `/assets/*` as immutable hashed content, and sends `no-cache` for HTML and SPA fallback responses.

## VM rollout runbook

Precondition: inspect the VM's **effective** Caddy routing before rollout. The VM has drift history. Confirm `/*` is served from `/srv/web`; if its active Caddyfile proxies to the Vite dev server instead, this change intentionally replaces that behavior.

From the repository root on the VM, after owner approval:

```sh
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml build web
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml up -d web
```

Then verify `/healthz`, `/`, and a representative SPA deep link; inspect response headers to confirm `Cache-Control: no-cache` for `/` and immutable caching for a hashed `/assets/*` file. Check Caddy's health after its normal rollout procedure as well.

## Rollback

Keep exactly **one** rollback image generation. To return to the prior dev-server behavior, restore the old Caddyfile first, then recreate only the base-compose `web` service (do not include the production overlay):

```sh
docker compose --env-file .env -f infra/compose/docker-compose.yml up -d --force-recreate web
```

This restores the source-mounted Vite service and its dev-server routing expectation. Retain only the single immediately preceding rollback image generation; do not accumulate rollback images.
