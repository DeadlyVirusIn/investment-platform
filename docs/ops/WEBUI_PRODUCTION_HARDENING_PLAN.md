# WebUI production hardening plan

Status: branch work only. This is **not deployed**. Owner approval is required before any deploy; deployment is a HARD STOP under project policy.

## Current state (production, as of 2026-07-15 rebuild report)

Production inherits the WebUI's Vite dev-server pattern: a `node:20-alpine` container with source bind-mounted at `/app`, followed by `npm install` and `npm run dev` at container start (unpinned dependency install on every recreate). Caddy has a `web_dist` static-volume path, but the volume has only ever been populated manually.

The prior `npm ci` build failure is fixed on this branch (commit `c19c453`). Root cause: the committed lockfile was generated by a different npm line than the builder's; regenerating it **inside the builder image** (`node:20-alpine`, npm 10.x, `npm install --package-lock-only`) makes `npm ci` deterministic in both Docker and local installs. If the lockfile ever drifts again, regenerate it the same way.

## Target architecture (implemented on this branch)

- `infra/docker/web.Dockerfile`: `npm ci` → `npm run build` (includes copy-lint + tsc) → dist staged at `/opt/dist` (outside `/app`, immune to the base compose bind mount).
- One-shot `web` service (prod overlay): runs `web-dist-sync` (baked into the image) which publishes new hashed assets first, `index.html` last, then prunes stale assets — an interrupted sync never leaves the live tree empty or serves cacheable 404s for assets.
- Caddy serves the SPA from `web_dist` with `/healthz` (both sites), `Cache-Control: public, max-age=31536000, immutable` for `/assets/*`, `no-cache` for HTML/SPA fallback, gzip/zstd, and the existing security headers. Compose healthcheck probes `/healthz` on the :8081 site.
- Overlay uses `!reset` on `ports`/`environment` for `web` (and `ports` for `api`/`db`) because compose union-merges list keys — a bare `[]` override does not unpublish.

## VM rollout runbook

Precondition: inspect the VM's **effective** Caddy routing before rollout. The VM has drift history. Confirm the active Caddyfile serves `/*` from `/srv/web`; if it proxies to the Vite dev server instead, this change intentionally replaces that behavior — capture a copy of the live Caddyfile before overwriting.

From the repository root on the VM, after owner approval:

```sh
# 0. BACKUP the live serving config before any change (rollback source):
cp infra/caddy/Caddyfile ~/backups/Caddyfile.pre-webstatic.$(date +%Y%m%d)
docker inspect caddy:2-alpine >/dev/null 2>&1 && \
  docker tag $(docker compose -f infra/compose/docker-compose.yml \
    -f infra/compose/docker-compose.prod.yml images -q caddy) \
    caddy:rollback-pre-webstatic 2>/dev/null || true

# 1. Build the dist image and populate the volume. The 'web' service is a
#    one-shot: run it in the FOREGROUND so publishing completes before Caddy
#    is recreated (do NOT use detached -d here, or verification can race the
#    still-running publisher):
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml build web
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml run --rm web
# Expect "web dist synced" and exit 0 before continuing.

# 2. Activate the new Caddyfile + compose healthcheck — Caddy MUST be
#    recreated (the Caddyfile is a read-only bind mount and the healthcheck
#    lives in compose metadata; neither applies to a running container):
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml up -d --force-recreate caddy
```

Verify: `curl -fsS http://127.0.0.1:8081/healthz` → `ok`; `/` → 200 with `Cache-Control: no-cache`; a SPA deep link (e.g. `/today/pick/GE`) → 200; a hashed `/assets/*.js` → 200 with `immutable` + `Content-Encoding: gzip`; `/api/health` → 200 through the proxy; `docker ps` shows caddy healthy. Then the public URL end-to-end.

## Rollback

Keep exactly **one** rollback image generation. Rollback must also restore Caddy, not just the web service:

```sh
# 1. Restore the previous Caddyfile (from the pre-rollout copy / git)
# 2. Recreate caddy so the restored config is active:
docker compose --env-file .env \
  -f infra/compose/docker-compose.yml \
  -f infra/compose/docker-compose.prod.yml up -d --force-recreate caddy
# 3. If returning to the dev-server pattern, recreate web from the BASE file only:
docker compose --env-file .env -f infra/compose/docker-compose.yml up -d --force-recreate web
```

Note: rolling back to the dev-server pattern only makes the site reachable again if the restored Caddyfile routes to it (the pre-rollout live Caddyfile captured in step 1 of the runbook). Verify the same URL checklist afterwards.
